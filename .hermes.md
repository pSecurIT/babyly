# Babyly — Hermes Project Rules

When working in this repo, follow these conventions.

## Build & Test

- **Dev**: `cd E:\code\Baby\web && npm run dev` (starts Prisma dev DB + Next.js)
- **Build**: `npm run build`
- **Test**: `npm run test` (Vitest), `npm run test:e2e` (Playwright)
- **Lint**: `npm run lint`
- **Prisma**: `npx prisma db push` after schema changes

## Architecture

- **Framework**: Next.js 16 (App Router) + React 19 + TypeScript
- **Database**: PostgreSQL via Prisma ORM
- **Auth**: Access code + magic link (guest) / admin allowlist (magic link)
- **Email**: Resend (production), console (dev)
- **Styling**: Tailwind CSS v4
- **Deploy**: Docker Compose + Caddy on Linode (Debian 13)

## Key Patterns

### Server Actions
All mutations use `"use server"` actions in `src/app/deelnemen/actions.ts` and `src/app/admin/actions.ts`. They:
- Validate CSRF token via `validateCsrfToken(csrfTokenFromForm(formData))`
- Check session (`readGuestSession` / `readAdminSession`)
- Redirect on failure with `?error=...` params
- Use Prisma transactions for atomic writes

### CSRF Protection
- Middleware (`middleware.ts`) sets `baby_csrf` cookie (HttpOnly, Secure, SameSite=strict) on every request
- Forms include hidden `<input name="csrfToken" value={csrfToken} />`
- Server validates via `isValidCsrfToken(formToken, cookieToken)` (constant-time hex compare)
- Local bypass: `ENVIRONMENT_NAME="baby-local" CSRF_BYPASS_LOCAL_ONLY="true"` in `.env` (dev only)

### Sessions
- Signed cookie `baby_session` with HMAC-SHA256 (`SESSION_SECRET`)
- Payload: `{ sub, scope: "guest"|"admin", exp, crossPromptSeen? }`
- 24h TTL, HttpOnly, Secure (prod), SameSite=lax
- Cross-prompt tracking stored in session to show once per direction

### Rate Limiting
In-memory `Map` (replace with Redis for multi-instance). Keys:
- `code:{ip}` — 15 req / 10 min (access code attempts)
- `mail:{ip}` — 10 req / 10 min (magic link requests)

### Magic Links
- Token: 32 random bytes → hex (64 chars)
- Stored as SHA-256 hash only
- TTL: `MAGIC_LINK_TTL_MINUTES` (default 1440 = 24h)
- Single-use enforced by atomic `usedAt` update
- Generic responses to prevent email enumeration

## Data Model (Prisma)

```
Participant (id, name, email@unique, emailVerifiedAt, createdAt, updatedAt)
  └─ Prediction? (participantId@unique, predictedName, gender, weightGrams, heightCm, predictedBirthAt, createdAt, updatedAt)
  └─ AddressCard? (participantId@unique, recipientName, street, houseNumber, postalCode, city, country, createdAt, updatedAt)
  └─ MagicLinkToken[] (email, tokenHash, purpose: guest_login|admin_login, expiresAt, usedAt?, createdAt)
AccessCode (id@single, codeHash, createdAt, updatedAt)
AdminAllowlist (id, email@unique, createdAt)
```

Constraints enforced server-side:
- 1 prediction per participant (unique FK)
- 1 address per participant (unique FK)
- Prediction edit: transaction checks existing → create or update

## Environment Variables

| Variable | Required | Description |
|----------|----------|-------------|
| `DATABASE_URL` | yes | PostgreSQL connection string |
| `APP_BASE_URL` | yes | Public origin (e.g., `https://baby.example.invalid`) |
| `ACCESS_CODE` | yes | Secret access code (hashed in DB) |
| `SESSION_SECRET` | yes | ≥32 random chars for session signing |
| `MAGIC_LINK_TTL_MINUTES` | no | Default 1440 |
| `EMAIL_DELIVERY_MODE` | yes | `console` or `provider` |
| `RESEND_API_KEY` | if provider | Resend API key |
| `EMAIL_FROM` | if provider | Sender address |
| `ADMIN_EMAILS` | yes | Comma-separated, exactly 2 |
| `PRIVACY_CONTACT_EMAIL` | yes | For privacy page |
| `PREDICTION_DEADLINE_DATE` | yes | ISO date string (deadline for predictions) |
| `CSRF_BYPASS_LOCAL_ONLY` | dev only | `true` to disable CSRF locally |
| `ENVIRONMENT_NAME` | dev only | Must be `baby-local` for CSRF bypass |

## Security Checklist (verify on changes)

- [ ] No secrets in code / logs / URLs
- [ ] All mutations: CSRF + session check
- [ ] Rate limits on auth endpoints
- [ ] Magic links: hash only, single-use, TTL, generic errors
- [ ] Admin: allowlist check server-side, separate session scope
- [ ] Security headers via `next.config.ts` (CSP, HSTS, etc.)
- [ ] CSV export: formula injection neutralization, no-cache headers
- [ ] No PII in logs (only `[event_name]` audit events)

## Testing

- Unit: `src/lib/**/*.test.ts` (Vitest)
- E2E: `web/e2e/` (Playwright)
- Full E2E requires `E2E_RUN_FULL=1` + ephemeral PostgreSQL (CI does this)
- Global setup creates/cleans test participant in `e2e/.auth/guest.json`
